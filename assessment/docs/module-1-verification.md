## 用户要求的重点

| 重点 | 验证内容 |
| --- | --- |
| 三类结论 | 全部完成且无问题为非问题件；缺失适用必查项或清单未确认为无法判定；确定问题与未完成项共存仍为问题件，并保留两种单项结果 |
| 缺失后继续检查 | 缺字段、不完整、冲突、无来源、空值、非法金额、负数、规则来源校验失败及服务异常均不会阻止后续独立检查；进度仍记录后续检查完成 |
| 年龄边界 | 10周岁前一天、恰好10周岁、次日，18周岁前一天、恰好18周岁、次日；年龄使用输入中明确指定的基准日，而不是系统当前日期 |
| 金额边界 | 20万、50万及300万限额的低于、等于、超过0.01的情况；采用 BigDecimal，等于不超限；核对所属人员、类型、币种、时点、是否包含本单及计算口径 |
| 同编码分支 | 两条 YBCR0045 使用不同分支ID，结果、来源及证据分别保留，两条均执行适用性判断，不按编码去重 |

年龄样例中的日期基准、风险保额字段、人员与金额口径均是测试约定，不是公司业务口径。恰好18周岁时两条未成年人规则均不适用；测试仅在“这两条是本合成场景已确认的完整清单”前提下允许非问题件，不代表真实18周岁保单可以免除其他检查。

## 本次发现并修复的问题

首轮70个测试中12个失败，暴露以下缺陷。修复后增加对新增校验与模拟标记各来源的独立用例，最终80个全部通过。

1. **范围不匹配仍执行规则**：原实现只影响完整性标记，却允许其他产品或渠道规则产生问题。现在不匹配的规则集不执行外部核验，每项记录无法完成，整单无法判定。
2. **无效条件被当成不适用**：零宽／反向／负年龄区间、负限额、缺少检查类型或条件、未知人员角色等，现在在适用性判断前校验，不能输出通过或确定问题。
3. **分支标识碰撞**：重复独立ID，或同编码同分支重复，记录无法完成；同编码的不同分支合法共存。
4. **缺失项丢失已有证据**：缺金额等情况保留已取得的年龄适用性证据，并在原因中标出缺失或冲突的字段。外部异常原文不进入报告，避免泄漏数据或凭据。
5. **模拟标记不完整**：合成输入、模拟规则、模拟服务、模拟影像结果任一存在，报告均标为模拟；尚未声明性质的服务适配器默认按模拟处理。
6. **独立模块父POM解析**：增加空 relativePath，使 assessment 直接解析 Spring Boot 父POM，避免尝试将原项目 pom.xml 当作父工程。

同时验证规则版本、确认人、确认记录和范围说明缺失时不执行检查。此校验只是核心入口的完整性防护，不替代后续规则发布模块的真实身份和审批校验。
